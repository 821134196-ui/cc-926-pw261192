# 固定延迟服务：固定并发 vs 排队时延动态并发调节

一个零依赖的离散事件仿真 + 可视化页面，演示在**固定服务延迟**工况下，
两种准入策略面对同一条压力曲线（基线 → 突发 → 回落恢复 → 中载过载 → 基线）的表现。

## 运行

```bash
cd delay-concurrency-demo
python3 -m http.server 8000
# 浏览器打开 http://127.0.0.1:8000/index.html
```

模块均为原生 ES Module，无构建步骤、无第三方依赖。Node 下可直接验证仿真：

```bash
node -e "import('./sim.js').then(m => console.log(m.runComparison().dynamic.summary))"
```

## 文件

| 文件 | 作用 |
|---|---|
| `sim.js` | 离散事件仿真核心（无 DOM 依赖）：到达流生成、准入、队列、固定延迟服务、AIMD 调节器 |
| `chart.js` | 零依赖 Canvas 时间序列图：阶段底纹、参考线、十字线 tooltip、HiDPI、明暗主题 |
| `index.html` | 页面：参数滑块、KPI 卡片、四张对比图、普通/高优先明细表 |

## 模型要点

- **固定延迟工况**：服务时间恒定 200ms，25 个 worker，系统真实能力 125 req/s。
- **并发限流语义**：请求准入即占用一个 permit（排队中 + 服务中都计数），
  达到并发上限立即快速拒绝（fail-fast），不堆积无界队列。
- **动态调节器（AIMD）**：每 0.5s 评估一次 EMA 排队时延
  - 高于目标 ×1.5 → 乘性减（下调 20%，单步最多 4）——突发时快速收敛；
  - 低于目标 ×0.5 → 加性增（每周期 +1）——回落后缓慢恢复，避免振荡；
  - 死区内保持不变；limit 始终钳制在 [8, 40]，**变化幅度受限**。
- **低频高优先请求**（2 req/s）：不受普通 permit 上限约束，可使用全部 worker
  外加 4 个专用排队位，并在调度时队头优先——拥塞时仍有机会进入（仿真中 0 拒绝）。
- **同一条压力曲线**：到达流由固定种子的泊松过程预生成，两种模式逐 tick 复用，
  「换一条压力曲线」按钮只更换种子。

## 默认参数下的典型结果

| 模式 | 完成 | 拒绝 | 拒绝率 | 平均/峰值排队 |
|---|---|---|---|---|
| 固定并发（limit=20，能力 100/s） | 3,304 | 1,328 | 28.7% | 0 / 0 ms（超额当场拒绝） |
| 动态并发（AIMD，8–40） | 3,704 | 928 | 20.0% | 25 / 200 ms（排队有界） |

动态模式在突发期把 limit 从 40 收敛到约 28，流量回落后加性恢复到稳定态；
高优先请求在两种模式下均全部准入。
